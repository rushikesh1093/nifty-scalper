## High-level view

The feed fix replaces all 4 occurrences of the undefined `_WsState` enum with `ws.closed` property checks, addressing the NameError that crashed the WebSocket connection.

The regime backend adds two new endpoints: `/api/regime/current` reads from Redis to return the current regime status with a live duration counter, and `/api/regime/history` queries the PostgreSQL `regime_states` table for recent transitions. Both endpoints follow the async/await pattern and use proper error handling, though the Redis field mapping is incorrect.

The regime frontend creates three polling components: RegimeStatus (5s refresh) displays a color-coded badge in the StatusBar, RegimePerformance (30s) shows a P&L table, and RegimeTimeline (60s) renders a visual timeline of regime changes over 24 hours. A new `/regime` page and navbar link were added. The components follow existing patterns with inline styles and CSS vars, but the API base URL in RegimePerformance doesn't match the router registration path.

The integration is structurally complete but has two blocking issues: the RegimePerformance component will always 404, and the `/api/regime/current` endpoint will always return `since: null` because it reads the wrong Redis field.

## Feed WebSocket state check replacement

The feed.py module referenced `_WsState.OPEN` in 4 locations but never imported or defined the enum, causing a NameError at runtime. The fix replaces all 4 occurrences with `not self._ws.closed`, which is the correct way to check WebSocket connection state in the websockets library (v12.0+).

Fixed locations:
- Line 214: `is_connected` property returns `self._ws is not None and not self._ws.closed`
- Line 305: heartbeat loop checks `if self._ws and not self._ws.closed:`
- Line 358: `send_subscribe` checks `if not self._ws or self._ws.closed:`
- Line 374: `send_unsubscribe` checks `if not self._ws or self._ws.closed:`



## Regime backend endpoints

Two new endpoints were added to `regime.py`:

`GET /api/regime/current?underlying=NIFTY` reads from Redis key `regime:{underlying}:current`, calculates `seconds_in_regime` from the stored timestamp, and returns `{regime: "UNKNOWN", since: null, seconds_in_regime: 0}` if the key doesn't exist. The Redis read bypasses `redis_cache.get()` and manually parses JSON. The field name is wrong: RegimeState stores `timestamp`, not `since`. The endpoint reads `data.get("since")` which will always be None, so `since_dt` will fail to parse and the exception handler will return `since: null` for every request. The live counter in the frontend will reset to 0 every 5 seconds instead of incrementing.

`GET /api/regime/history?underlying=NIFTY&hours=24` queries the `regime_states` table for rows where `underlying` matches and `timestamp >= now - hours`, ordered by `timestamp DESC`. Float conversions handle nullable columns (`r.adx` could be None).

Both endpoints are registered at `/api/regime`, not `/api/v1/regime` like other routers. This creates a path mismatch with the RegimePerformance component and the getCurrentRegime/getRegimeHistory API functions.

## Frontend type definitions and API functions

Two new interfaces were added to `types/market.ts`: `RegimeStatus` with `{regime, since, seconds_in_regime}` and `RegimeHistoryEntry` with `{regime, timestamp, adx, atr, previous_regime}`.

Two API functions were added to `lib/api.ts`:

```typescript
getCurrentRegime = (underlying = "NIFTY") =>
  api.get<RegimeStatus>(`/regime/current`, { params: { underlying } })

getRegimeHistory = (underlying = "NIFTY", hours = 24) =>
  api.get<RegimeHistoryEntry[]>(`/regime/history`, { params: { underlying, hours } })
```

Both use the shared `api` axios instance with `baseURL: "http://localhost:8000/api/v1"`. The paths `/regime/current` and `/regime/history` will resolve to `/api/v1/regime/current` and `/api/v1/regime/history`, but the router is registered at `/api/regime`, not `/api/v1/regime`. These calls will 404.

RegimePerformance creates its own axios instance with `baseURL: "http://localhost:8000/api/v1"`, then calls `api.get("/regime/performance")`. The resulting path `/api/v1/regime/performance` doesn't exist because the regime router prefix is `/api/regime`.

## RegimeStatus component and StatusBar integration

RegimeStatus polls `getCurrentRegime("NIFTY")` every 5 seconds. Two effects manage the live counter: one syncs `liveSeconds` state with `data?.seconds_in_regime` on refetch, another runs a 1-second timer to increment `liveSeconds`. This creates a smooth counter that ticks every second and resyncs every 5 seconds. If the backend returns stale data (regime changed but Redis hasn't updated), the counter will drift until the next refetch.

The component is integrated into StatusBar after the Broker section with a `borderRight` divider.

## RegimePerformance component

RegimePerformance polls `/regime/performance` every 30 seconds and renders a table with columns: Regime, Strategy, Total Trades, Win Rate, Total P&L, Avg P&L. The component creates its own axios instance with `baseURL: "http://localhost:8000/api/v1"` then calls `api.get("/regime/performance")`, producing path `/api/v1/regime/performance`. The regime router is registered at `/api/regime`, so the real path is `/api/regime/performance`. This will 404.

## RegimeTimeline component

RegimeTimeline polls `getRegimeHistory("NIFTY", 24)` every 60 seconds and displays a horizontal timeline as colored div blocks. Block widths are percentages of the total 24-hour period: `(durationMins / totalDuration) * 100%`. The last block's end time is `Date.now()`, so its duration extends to the current moment — the timeline will shift every minute as the last block grows.

Hover state is managed via `useState<number | null>`. The tooltip is positioned with `position: absolute`, `bottom: 100%`, `transform: translateX(-50%)` to center it above the block.

The legend shows all regime types with their colors, regardless of whether they appear in the data.

## /regime page and navigation

A new page at `app/regime/page.tsx` renders `RegimePerformance` and `RegimeTimeline` stacked vertically with a 16px gap.

The NavBar's `LINKS` array was updated to include `{ href: '/regime', label: 'Regime' }`.
